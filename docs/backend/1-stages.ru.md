# 1. Ваши стадии

Стадия — единственное место в StageFlow, где выполняется ваш код. Всё
остальное — ветвления, циклы, обработка ошибок, фрейм — дело графа, а граф
это JSON, который вполне мог нарисовать кто-то другой.

```python
from stageflow import BaseStage, register_stage

@register_stage("LoadTicketStage")
class LoadTicketStage(BaseStage):
    """
    description: "Берёт подготовленный тикет из data/tickets.json"
    icon: "/icons/ticket.svg"
    category: "support.data"
    arguments:
      ticket_id:
        type: string
        optional: true
        description: "Идентификатор тикета (T-1001); пусто — первый в файле"
    outputs:
      text:
        type: string
        description: "Сообщение клиента"
      customer_id:
        type: string
        description: "Кто написал"
    """

    async def run(self):
        wanted = (self.get_arguments().get("ticket_id") or "").strip()
        ...
        self.set_outputs({"text": ticket["text"], "customer_id": ticket["customer_id"]})
```

Докстринг — не документация, которую заодно парсят, а **и есть** спека:
редактор рисует по ней карточку — имя, иконку, цвет, какие порты есть и
зачем каждый. Полная грамматика — на странице
[Спецификация стадии](../stage-specification.ru.md); здесь важно другое:
записать это больше негде, поэтому оно не может разойтись с кодом под ним.

## Маленькие, и про одно

Стадии в примере намеренно крошечные: загрузить тикет, классифицировать,
поискать в базе знаний, отрисовать ответ, отправить, эскалировать. Это не
аккуратизм. **Узел на холсте — это стадия**, и стадия, которая и ищет что-то,
и решает, что с найденным делать, превращается в узел, чей смысл приходится
угадывать по имени. Решения место в графе, в виде `condition` или `switch`,
где их видно и с ними можно спорить.

Проверка простая: если в описании нужно слово «и», это две стадии.

## Аргументы приходят из фрейма

Стадия никогда не читает фрейм. Ей передают аргументы, а откуда они взялись —
говорит граф:

```json
{
  "id": "classify",
  "type": "stage",
  "stage": "ClassifyByRulesStage",
  "arguments": {"vars": {"text": "text", "subject": "subject"}},
  "outputs": {"topic": "topic", "urgency": "urgency"},
  "next": "search"
}
```

`arguments.vars` связывает имя аргумента с переменной фрейма,
`arguments.const` — с литералом, а ключ, оканчивающийся на `.`, делает
значение [CEL-выражением](../expressions.ru.md). `outputs` работает в обратную
сторону. Стадия видит обычный словарь и возвращает обычный словарь — за счёт
этого её можно тестировать вообще без пайплайна, и за счёт этого же одна
стадия может стоять в графе дважды и читать разные переменные.

## Ошибки — это дороги

Упавшая стадия сообщает графу, что случилось, а граф решает. Работает это
только если исключения различимы:

```python
class LlmAuthError(RuntimeError):      # ключа нет — падаем на правила
class LlmRateLimited(RuntimeError):    # 429 — поможет retry с паузой
class LlmUnavailable(RuntimeError):    # 5xx — retry тоже поможет
class LlmBadAnswer(RuntimeError):      # модель ответила не тем
```

Четыре класса, а не один, потому что в графе это четыре разные дороги:
`retry` на двух временных, `except` вниз на ключевые слова на первом, отдельная
концовка на последнем. Единственный голый `Exception` не оставил бы автору
пайплайна ничего, на чём ветвиться, — см.
[Ошибки и повторы](../errors.ru.md).

## События и текст по мере написания

Стадия может испускать события, и они попадают в лог редактора по ходу
прогона:

```python
allowed_events = [
    EventSpec("reply_sent", "Ответ ушёл клиенту",
              payload_schema={"ticket_id": str, "channel": str, "chars": int}),
]

self.emit("reply_sent", {"ticket_id": ticket_id, "channel": "email", "chars": len(reply)})
```

Объявить их стоит трёх строк: необъявленный тип отвергается, так что опечатка
в имени события ловится, а не производит тихо событие, которого никто не ждёт.

Одна форма payload — контракт, а не соглашение. Всё, что содержит
`{"stream": true, "text": "…"}`, редактор считает куском текста, который узел
пишет прямо сейчас, и показывает в колонке отладочной панели по мере
поступления:

```python
for word in reply.split(" "):
    self.emit("reply_chunk", {"stream": True, "text": word + " ", "label": "Reply"})
```

Редактор ничего не знает здесь ни про ботов поддержки, ни про языковые модели
— он знает форму payload. Стадия расшифровки речи или стадия сборочного лога
получают то же самое бесплатно, а `label` — это как называется колонка.

## Регистрация

`register_stage` кладёт класс в **глобальный на процесс** реестр — именно это
и делает возможным `get_stages()`, а значит и `/api/stages`:

```python
# app/stages/__init__.py
from . import support, llm  # noqa: F401 - импорт их и регистрирует
```

Глобальный — это и есть та фраза с последствиями со
[вступления](index.ru.md): каждая импортированная процессом стадия доступна
каждому пайплайну в нём. Пока пайплайны пишете вы, это нормально. Это
перестаёт быть нормальным ровно в тот момент, когда их пишет кто-то другой, —
о чём [шаг 3](3-policy.ru.md).
