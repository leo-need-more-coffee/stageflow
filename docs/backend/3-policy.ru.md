# 3. Что можно собирать

Вот фраза из [шага 1](1-stages.ru.md) вместе с её последствием:
`register_stage` кладёт класс в **глобальный на процесс** реестр, поэтому
каждая импортированная процессом стадия доступна каждому пайплайну в нём.

Пока пайплайны ваши — нормально. Это перестаёт быть нормальным, как только
они не ваши, — а «разработчик определяет блоки, кто-то менее доверенный их
собирает» и есть та схема, ради которой StageFlow существует. Без чего-то
ещё `ChargeCardStage` доступна любому JSON, который кто угодно запостил.

Это «что-то ещё» — [`Policy`](../policy.ru.md): её задаёт хост, из пайплайна
её не прочитать и уж точно не расширить.

```python
from stageflow import Limits, Policy

BASIC = Policy(
    stages={"LoadTicketStage", "ClassifyByRulesStage", "SearchKnowledgeStage",
            "RenderReplyStage", "SendReplyStage", "EscalateStage",
            "SetValueStage", "ConcatStage", "TemplateStage"},
    node_types={"entry", "stage", "condition", "switch", "terminal"},
    limits=Limits(
        counters={"seconds": 15, "steps": 200, "kb_lookups": 20, "replies_sent": 1},
        gauges={"concurrency": 2, "depth": 2, "frame_bytes": 200_000},
        max_retries=2, max_delay_seconds=2,
    ),
)
```

Три вещи, и `None` в любой из них означает «нет мнения», что не то же самое,
что пустое множество: `Policy()` разрешает всё, `Policy(stages=set())` — ни
одной стадии.

## Два слоя, один и тот же ответ

```python
pipeline.validate(policy)                       # до: весь граф, сразу
Session(id=..., pipeline=..., policy=policy)    # во время: каждый узел, когда до него дошли
```

Валидация — то, по чему действует человек: она называет все проблемы разом,
чтобы граф можно было починить, а не выяснять по узлу за прогон. Проверка в
рантайме — то, что держит на самом деле, потому что граф может попасть в
сессию, ни разу не пройдя валидацию. Одно не заменяет другое, и формулировки
одинаковы в обоих случаях.

Пример валидирует прямо в обработчике запроса, ещё до старта потока:

```python
def start(self, payload: dict, policy: Policy) -> Run:
    pipeline = Pipeline.from_dict(payload.get("pipeline") or {})
    pipeline.validate(policy)      # отказ отвечает на POST, а не из потока через минуту
    ...
    session = Session(..., policy=policy)
```

## Сказать редактору, чтобы он сказал автору

Политика, о которой редактор не знает, — это политика, которую автор узнаёт
через отказ. Поэтому оба читающих эндпоинта сужены ею:

```python
@router.get("/stages")
async def stages(caller: CallerPlan) -> dict:
    policy = policy_for(caller)
    return {"stages": {name: cls.get_specs()
                       for name, cls in get_stages().items()
                       if policy.allows_stage(name)}}


@router.get("/meta")
async def meta(caller: CallerPlan) -> dict:
    policy = policy_for(caller)
    return {"api": 1, "plan": caller, **capabilities(policy), "limits": _limits_of(policy)}
```

Отдать спеку стадии, которую политика запрещает, — значит заставить редактор
нарисовать её в палитре, а прогон — отвергнуть: ровно то расхождение, ради
устранения которого политика и заведена, воспроизведённое одним эндпоинтом
позже. `capabilities(policy)` делает то же самое для типов узлов.

Что это даёт на дешёвом тарифе примера, если открыть пайплайн, которому нужен
`map`:

![Граф, который тариф не запустит, — сказано до запуска](../img/be-plan-refuses.png)

Четыре типа узлов в палитре погашены, на виноватом узле маркер, а в
статус-баре написано `per_ticket: plan 'basic' does not include a 'map' node`
— до того, как кто-нибудь нажал «Run».

## Что валидация проверяет и что отказывается угадывать

Против `limits` статическая валидация проверяет только то, что **достоверно
выводится из JSON**:

| Что проверяется | Почему это честно |
|---|---|
| кратчайший путь через граф против `steps` | любой прогон проходит не меньше узлов, значит граф, чей самый дешёвый путь не влезает, не завершится вообще |
| глубина вложенности объявленных субпайплайнов против `depth` | вложенность записана, а не вычисляется |
| что просит каждый `retry` против `max_retries` и `max_delay_seconds` | числа лежат в JSON |

Стоимости цикла в этом списке нет и не будет: число проходов приходит из
данных, а стоимость прохода — из его аргументов. Любое умножение здесь
отвергало бы работающие графы, а ложный отказ рабочему графу хуже того
потолка, ради которого он затевался.

## Потолок жёсткий

`BudgetExceeded` наследует **`BaseException`** и намеренно стоит вне иерархии
`StageFlowError`: блоки `try` ловят `Exception`, и машинка `retry` тоже, — а
тенант, способный обернуть граф в `try` и проглотить отказ, превратил бы
любой лимит в украшение. Ловит его ровно одно место, `Session.run`, и
заканчивает прогон так же, как это делает `stop`:

```python
result.result   # {"status": "budget_exceeded", "meter": "kb_lookups", "limit": 20, "spent": 21}
result.meters   # всё потраченное — по нему и выставляется счёт
```
