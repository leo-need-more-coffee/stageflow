# StageFlow

Фреймворк описания и исполнения пайплайнов, заданных JSON: граф узлов,
пользовательские стадии, иммутабельный фрейм данных, CEL-выражения, retry
и блочный `try/except`, параллельные ветки, циклы по списку,
вложенные пайплайны и лимиты на всё это для каждого тенанта.

```bash
pip install stageflow-framework
```

Требуется Python 3.11+ (его требует CEL-байндинг `common-expression-language`).

![Пайплайн в редакторе StageFlow](img/tut-final.png)

На картинке — [редактор](https://github.com/leo-need-more-coffee/stageflow-ui):
отдельная веб-страница, которая рисует и отлаживает граф, пока ядро его
исполняет.

## С чего начать

Впервые здесь? [Туториал](tutorial/index.ru.md) собирает рабочий пайплайн шаг
за шагом, со скриншотами из редактора. А когда пайплайны пишете уже не вы,
понадобится вторая половина — [Свой бэкенд](backend/index.ru.md): ваши стадии
за HTTP-контрактом и политика, которая решает, что из них разрешено собрать
и сколько это может израсходовать.

## Свой бэкенд

Редактор не исполняет ничего: ваши стадии живут на вашем бэкенде. Пять шагов
разбирают [бэкенд-пример](https://github.com/leo-need-more-coffee/stageflow-example)
в том порядке, в каком его писали.

| Страница | О чём |
|---|---|
| [Что такое бэкенд](backend/index.ru.md) | кто за что отвечает и что мы собираем |
| [1. Ваши стадии](backend/1-stages.ru.md) | `register_stage`, спецификации, аргументы, события, стриминг |
| [2. Эндпоинты](backend/2-endpoints.ru.md) | семь эндпоинтов, настоящая `Session`, SSE, CORS |
| [3. Что разрешено собирать](backend/3-policy.ru.md) | своя `Policy` на каждый вызов и как предупредить редактор |
| [4. Во что обходится прогон](backend/4-metering.ru.md) | `reserve:`, `charge()`, собственные счётчики |
| [5. Чей это запрос](backend/5-tenants.ru.md) | тарифы, ключ доступа и где стоит проверка |
